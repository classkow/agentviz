## Hard rules (all verified by an independent checker script)
1. Every question must be answerable from that lesson's own prose or demo data. No outside knowledge points.
2. explanation must cite a real section: use the pattern 见「<section name>」一节 (zh) / See the "<section name>" section (en), where <section name> is an exact h2 heading that EXISTS in that lesson's markdown. Zero tolerance: the checker regex-matches every citation against the lesson's h2 list.
3. Never invent numbers. Any number in a question/option/explanation must appear in that lesson's prose or demo JSON (checker cross-references).
4. zh/en pairs must align per lesson: same question count (3), same order, same answer index, same option count (checker compares).
5. distractor options must be plausible but clearly wrong to someone who read the lesson; avoid absurd joke options.
6. Keep JSON valid UTF-8, 2-space indent, no trailing commas. File naming exactly matches the slug.
