「Agent」这个词被营销包装得很玄，但拆开看结构朴素得惊人：一个只会单次调用的模型，外面套一个循环，再递给它几件工具。这一课用最少的零件把这个结构拼出来。Anthropic 在《Building effective agents》里把这类系统分成两档：workflow（模型调用路径由你预先写死）与 agent（模型自己动态决定下一步做什么、做多久）——本课讲的是后者，以及它和前者的零件差异其实只有一层循环。

## 模型是单次调用

先把模型本身看死：一次 API 调用就是一次纯粹的函数——输入一段上下文，输出一段文本，仅此而已。它不会「再想想」、不会主动追问、没有跨请求的记忆，你不把历史重新发给它，它就当之前什么都没发生过。用 Qt 的话说，它是一个无状态的槽函数，不是一个有事件循环的对象。这一点必须钉死在脑子里，因为后面所有「自主性」的观感，都是外部代码在这个单次调用之上包出来的，模型对此一无所知。

## 给模型一个循环

Agent 的第一个零件不是更聪明的模型，而是一个 while 循环：调用模型 → 检查输出 → 如果模型要求做动作就执行并把结果拼回上下文 → 再调用一次。循环退出的条件由模型输出决定——它给出最终答案而不是动作请求时，循环结束。所谓「自主完成任务」，本质就是这个循环多转了几圈。Anthropic 把这种结构叫做 agent loop：模型在循环里根据自己的输出和环境的反馈动态规划路线，步数和路径都不预先固定。工程上它还配一个终止条件：最大迭代数或预算上限，防止永不收敛。

## ReAct：Thought-Action-Observation

循环每转一圈该按什么格式走？ReAct（Yao et al., 2022）给了一个被广泛沿用的答案：每圈固定三段。模型先输出 Thought——对当前局面的推理和下一步打算；然后给出 Action——从工具清单里选一个并给出参数；我们作为运行时真正执行这个动作，把结果作为 Observation 回灌进上下文，开始下一圈。Thought 是关键发明：让模型把推理显式写出来，再据此选动作，比直接吐动作准确得多，也留下了可审计的决策轨迹。这套三段式不需要训练新模型，纯靠提示词和解析就能在普通对话模型上跑起来。

## 一次完整任务回放

以「查明天北京天气并判断是否适合野餐」为例走一遍。第 1 圈：Thought「我需要明天的天气数据」→ Action `get_weather(city="北京", date="明天")`；Observation 返回「晴，14~26℃，微风」。第 2 圈：Thought「已有天气，还需判断野餐适宜性」→ Action `thinking`（或直接推理，无外部调用）；Observation 为模型自己的分析。第 3 圈：Thought「信息足够」→ 输出最终答案「适合，注意早晚温差」，循环退出。三圈、两次工具调用，路径是模型现场决定的——如果天气接口报错，它可能改道去查历史数据，这正是循环优于固定流程的地方。

## 失控与护栏

循环的反面是失控。常见三种死法：死循环——模型反复调用同一个注定失败的工具；错误累积——第 3 圈的错误 Observation 污染了后面所有判断；上下文爆炸——每圈都往 messages 里追加，几十圈后 token 费用和延迟双双失控。护栏因此是必备部件而非可选项：硬性最大迭代数、token/费用预算上限、高风险动作（删数据、发邮件）前的人工确认、对工具结果的长度截断。Anthropic 的建议是先按最简单的结构搭，能不用 agent 就用 workflow，必须用时把护栏当成和循环同等重要的一等公民来设计。
