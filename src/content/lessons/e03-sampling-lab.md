上一课看完了一次请求的完整旅程，这一课钻进服务端最关键的一步：逐 token 生成时，模型怎么从几万个候选里「挑出」下一个 token。正文上方的采样实验室把一组候选 token 的 logit 交到你手上，拖动温度、top-k、top-p 三个滑块，概率分布实时重塑，点「采样一次」就能亲手抽签。

## 概率从哪来

模型内部并没有「下一个词」的现成答案，只有一堆分数：词表里每个 token 各得一个 logit，它是个未归一化的实数分值，正负皆可。softmax 把这组 logit 变成合法的概率分布：先对每个值取指数（保证非负），再除以总和（保证加起来等于 1）——思路和你手写加权随机时「先求权重和、再按占比落点」完全一样。softmax 是指数放大器：一个 token 的 logit 每高出 1 分，它对其他候选的概率比就放大 e 倍（约 2.7 倍），所以分数上微小的差距会演变成悬殊的选中率。到这一步为止一切都是确定性计算，真正的「随机」发生在下一步：按这份分布抽签。

## 温度：分布的锐度

温度 T 作用在 softmax 之前：先把每个 logit 除以 T，再取指数。T 小于 1 时分数差距被拉大，概率向头部集中，分布变「尖锐」，输出更稳定、更可复现；T 大于 1 时差距被压平，长尾 token 也有机会出头，分布变「平坦」，输出更多样也更容易跑偏。可以把 T 理解成 Qt 信号链上的增益旋钮：输入信号不变，增益越大波形摆动越剧烈。T 趋近 0 相当于永远取 argmax（贪心解码），T 很大则趋近均匀抽签。在上方演示里拖动温度滑块，或点 0.2 / 1.0 / 2.0 三个预设档位，能直观看到同一组 logit 在三种形态之间的切换。

## top-k：硬截断

top-k 是一道硬闸门：按概率从高到低排序后，只保留前 k 个候选，其余全部置零，再把幸存者的概率重新归一化（除以它们的概率和），保证分布仍然合法。它像 C++ 里写死的 `resize(k)`：留下的候选数量是确定的，与内容无关——k=5 就永远只留 5 个，哪怕第 5、第 6 名的概率只差万分之一。好处是行为可控、实现便宜；坏处是「一刀切」：词表是十万级的，k 取小了可能掐掉有价值的候选，取大了又放进不少长尾噪声。在演示里把 top-k 滑块从 12 拉到 1，可以看到分布迅速退化成「只剩一名选手」。

## top-p：动态累积

top-p（又称核采样，nucleus sampling）换了一个切口：从概率最高的 token 开始累加，累加和达到 p 就封口，封口之后的候选全部舍弃，再对幸存者归一化。与 top-k 的差别在于候选数量是动态的：分布尖锐时，前两三名可能就占到 95% 的概率质量，只留两三个；分布平坦时则自动放宽到更多个——它按「概率质量」而非「名额」划线。代价是行为不如 top-k 直观：同一个 p，在不同温度下的候选数完全不同，两个参数会互相耦合。工程上通常二选一，或各取温和值组合使用，而不是同时收紧到极端。

## 组合拳与工程实践

三个参数在 HuggingFace transformers 的默认实现里按固定顺序串联（vLLM、TGI 等其他推理引擎的顺序可能不同）：先做温度缩放（softmax(logit/T)），再做 top-k 截断，最后做 top-p 累积截断并归一化——这也是本页演示采用的计算顺序。调参直觉可以按任务分：写作、头脑风暴类用高温（0.8\~1.2）加宽松 top-p，换取措辞多样；代码生成、信息抽取、结构化输出类用低温（0\~0.3）甚至直接贪心解码，追求稳定可复现。各家 API 不显式传 temperature 时默认多为 1.0；要记住，调这些参数改变的只是「抽签的分布」，而不是模型本身的能力。
