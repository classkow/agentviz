E04 说窗口不是记忆——每次请求结束，窗口里的内容就散了。可产品里的用户不知道这件事：他们期望「上次说过的你记得」。把这种期望落成工程，就是本课的记忆（memory）。上方的泳道时间轴把同一段 20 轮的对话跑了两遍记忆策略：滑窗版在第 20 轮把任务答错，摘要版答对——同一个模型，差别只在历史怎么留。

## 无状态模型与记忆的外挂本质

先把事实钉死：模型没有任何跨请求的状态。「记得上一轮」的唯一机制是把上一轮重新发进窗口——所谓记忆，全部是应用层在窗口之外做的存储与回填决策。这个认知决定了工程视角：记忆不是模型能力，是数据结构设计。你要为它选存储（内存、数据库、向量库）、选淘汰策略（留什么、丢什么）、选回填时机（全量带上还是检索带上）——每一个选择都直接改写回答质量与成本。E04 的预算表在这里续上了：记忆策略的本质，是在有限窗口里决定「哪段过去值得占未来几轮的位置」。用户对记忆的期望是分层的：记住说过的偏好（必须）、记住未兑现的承诺（必须）、记住全部原话（伪需求）——把期望分层，记忆策略才有的放矢。

## 滑窗：最简单，也最容易丢锚点

滑窗策略只保留最近 N 轮，更早的历史整段丢弃。实现成本几乎为零：一个定长数组。它的失败模式演示里看得清楚：第 1 轮立下的三条硬约束（预算、颜色、发票抬头）在第 20 轮结算时早已被挤出窗口，模型只能靠猜——开了个人抬头、总价超预算。滑窗的深层缺陷是「无差别」：它按时间淘汰，不管信息的重要性；而任务锚点往往出现在对话开头，恰好是被优先淘汰的位置。滑窗适合锚点密度低、对话结构松散的场景（闲聊、单轮问答串联）；只要任务有「开头立规矩、结尾用规矩」的结构，裸滑窗就是定时炸弹。

## 摘要压缩：用一次生成换大块预算

摘要策略把久远的历史压成一段摘要，近期的历史原样保留。演示里前 12 轮被压成约 200 token，加上近 8 轮的 1600，历史从 5200 降到 1800——窗口占用降 65%，三条约束 3/3 留存。摘要的关键纪律是「压缩不是丢弃」：约束、承诺、异常事件必须逐条写进摘要正文，而不是指望模型「大意记得」；摘要的生成也要用明确的结构约束（P01 的四件套同样适用）——「列出所有未兑现的承诺与硬约束」这样的摘要指令，比「总结一下对话」可靠得多。工程上摘要有两个触发时机：按 token 阈值触发（逼近窗口上限时压一次）与按轮数触发（每 N 轮滚存一次）；摘要在后台异步生成即可，不必阻塞当前请求。代价也要算清：每次压缩多付一次模型调用，且摘要有失真风险——数字、日期、专名在摘要里最容易走样，关键值要用引文原样保留。

## 外部存储：保真度最高的重炮

第三种策略把记忆彻底搬出窗口：对话要点、用户画像、任务状态存进数据库或向量库，需要时检索回填。保真度最高——什么都不丢，而且天然支持跨会话：今天记住的偏好明天还在。代价是实现最重：要维护存储结构、写检索逻辑、决定「什么时机取什么回来」，每一步都可能引入新的失败面。它与 R02/R03 的检索技术完全同构——事实上「把历史当知识库检索」就是 RAG 思想用在记忆上；外部存储还顺带解决了窗口外内容的可审计性——存了什么、什么时候存的，库里有账。实践中的分层组合最常见：滑窗保近期、摘要保中期、外部存储保跨会话长期，三层各司其职；Generative Agents 的记忆流（检索 + 时间与重要性加权）是这一路线的经典设计。

## 取舍表与隐私边界

三种策略放一张表里看：保真度——滑窗最低、摘要居中、外部存储最高；成本——滑窗近乎免费、摘要每次压缩一次调用、外部存储加上检索调用；实现复杂度——同序递增。选型的第一问不是「哪个先进」，而是「任务的锚点活多久」：单会话短任务滑窗够用；多轮任务型对话至少要摘要；产品要「记得用户」就得外部存储。最后是隐私边界：跨会话记忆意味着留存个人信息——留存多久、用于什么、用户能否查看与删除，这些不是法务套话而是功能设计；「记住一切」在产品上是卖点，在合规上是负债。记忆是 Agent 变可爱的原因，也是它最需要被约束的地方。
