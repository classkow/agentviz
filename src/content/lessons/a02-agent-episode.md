上一课 A01 交出的是抽象结构：一个单次调用的模型，外面套循环，再递给它工具。这一课把结构换成具体的一集任务。正文上方的演示是一条完整的执行轨迹——5 条泳道、13 个事件，从用户提出目标到摘要交付，可以逐拍播放、前进、后退或点行跳读。看的时候盯住两件事：谁在决定下一步，以及谁在执行。

## 从单次调用到完整任务：什么是 episode

E01 那条链路是一次性的：一段上下文进去，一段文本出来，请求结束就归零。可「帮我查疲劳数据并写成一页摘要」这种任务，一次调用通常给不出答案——它得先去查，看完再决定查什么。episode（一集）就是描述这种形状的术语：从用户给出目标开始，到系统交付或放弃结束，中间模型被调用若干轮、工具被执行若干次、结果被回填若干遍。它靠的不是更聪明的模型，而是同一个无状态模型被循环反复调用。演示里的 13 个事件，就是这一集被拆开后的全部拍数。

## 循环的三拍：思考、动作、观察

这一集反复出现同一个节奏，A01 里提过的 ReAct 三段式：思考、动作、观察。思考是一次普通的 chat 调用，和平时问答没有区别，唯一差别是输出不是答案而是一个决定——演示里三次「思考调用」分别产出检索计划、修订计划与汇总结构。动作是模型写出的结构化调用请求：函数名加一段参数 JSON，真正的执行发生在客户端。Anthropic 的文档把这一步讲得很硬：模型只生成 tool_use 块，代码由你跑，结果再由你以 tool_result 回传。观察是执行结果全文回填进上下文，成为下一轮思考的输入。

## 一集回放的五个决策点

对照演示数一遍，这一集里有五个点是模型自己定的：任务拆解（a1、a2，把一句话分成检索与汇总两件事）、旧数据甄别（a5、a6，识别出 2019 年旧版目录不可直接引用）、计划修订（a6 到 a7，发现缺工况数据就补一次 fetch）、汇总结构（a9，决定先摆工况对照再给缺口）、退出时机（a13，判断数据够了就收手）。五个点没有一处是预先写死的 if 分支——这正是 Anthropic 区分 workflow 与 agent 的那条线。每个决策点模型手里的原料，只有截至那一轮已经累积起来的上下文。

## 上下文在循环里怎么长

单次调用只有一个输入；一集任务里，第 k 轮思考要把前 k-1 轮的全部对话重新发一遍，因为模型无状态。所以每轮观察都不是白拿的：5 条检索命中、一整页曲线数据都留在上下文里，按轮累计的输入 token 近似平方增长，费用和延迟跟着涨。更长的那个隐患是注意力——上下文越厚，模型对早期内容的把握越难保证，表现为重复动作、忘记已经拿到的数据。这类失控前兆的工程对策是截断与压缩（E04 展开）加硬护栏（A07 展开）。

## 让循环停下来：停止条件与可审计性

循环不会自己收敛，停下来靠两样东西。一是任务完成判定：模型这一轮给出的不再是动作请求，而是最终答案，例如演示里的 a10。二是外部硬闸门：轮数上限、时间与费用预算、高风险动作前的人工确认——Anthropic 明确建议给 agent 设最大迭代数，防止它永不停歇地转。演示里的 a13 属于前一种：计划跑完、答案已出。后一种在真实系统里同样必须就位，只是这一集没转到那个上限。另一份收获在 a11：把每轮的引用与被丢弃的数据归档成副产品，这集任务才经得起人工复核，「多轮自主」也才不只是「多轮不可解释」。

## 演示数据说明

上方演示是教学示意，不是真实运行的录制日志：U 型螺栓的载荷-寿命数值、检索命中的条数与年份均为构造示例，别当成工程数据引用。事件形状对齐真实调用链——三次独立的 chat 调用、两次客户端执行的工具请求、两条回填的观察结果，字段语义与 Anthropic 工具使用文档描述的 tool_use / tool_result 往返一致。写作口径与 E01、A01 相同：构造的是数字，真实的是结构。请把这一集当作形状上的参考，真要拿去用，数值仍要回到你自己的检索源逐条核对。
