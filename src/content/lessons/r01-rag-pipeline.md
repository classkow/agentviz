## 为什么需要开卷：闭卷模型的两个缺陷

把 LLM 想成一位只读过训练截止日前所有书的闭卷考生：此后发生的事、没进过语料的私有资料，它一概不知道——这是知识冻结。更麻烦的是第二点：闭卷答题时它不会交白卷，缺什么就按语言惯性补什么，答得流畅却毫无依据，这就是幻觉。问「我们公司第三季度的回款政策」，模型没见过这份文件，得到的只会是像模像样的泛泛而谈。RAG（检索增强生成）的思路不是去改造模型，而是换一种考试形式：先从资料库里把相关段落查出来，连同问题一起交给模型，让它开卷作答。

## 索引期：把文档压进几何空间

索引期是离线的准备工作，相当于编译期：离线预处理跑一次，产物是可复用的索引文件，查询期（运行期）直接加载使用。流程四步：先清洗文档，去页眉页脚、表格转文本；再切块，常见配置是每块约 512 token、相邻块重叠 64 token——重叠保证恰好跨界的句子在相邻两块里各留一份，不会被拦腰切断；然后调用嵌入模型，把每块文本编码成一个高维浮点向量，语义越接近、向量之间夹角越小，文字从此变成可计算的几何坐标；最后把向量、原文、元数据三件套写入向量库。这里有一条铁律：嵌入模型一旦选定即冻结，建库与查询必须用同一个，不同模型的向量空间互不兼容。索引期是一次性成本，只在知识库更新时重跑。

## 查询期：一次开卷请求的四步

查询期是运行期，每次提问都完整走一遍，共四步。第一步把用户问题用同一个嵌入模型编成向量，只处理一句话，毫秒级完成；第二步拿它去向量库做余弦相似度检索，取最相近的 top-k 段落，连同原文与元数据一起返回；第三步拼增强 prompt：system 写明「仅依据以下资料回答，标不出来源就明说」，后面接上检索到的资料原文与用户问题；第四步按 E01 讲过的老协议 POST /chat/completions 发出，流式收回结果。RAG 的关键认知在这里：它不发明新的调用协议，改写的只是请求体内容——messages 里多了几段检索资料，temperature 通常调低（如 0.2）以减少无据发挥。

## 相似度与 top-k：检索质量的两个旋钮

余弦相似度衡量两根向量夹角：接近 1 表示方向几乎一致、语义高度重合，接近 0 表示基本无关；检索就是用 query 向量在库里找得分最高的几条。top-k 是第一个旋钮：k 太小会漏掉关键资料，答案残缺；k 太大则稀释上下文——演示数据里第 5 条得分已跌到 0.42，属于弱相关，把它拼进 prompt 不但帮不上忙，还挤占上下文窗口、诱导模型牵强附会。实际工程会给相似度设阈值，低分块宁可丢弃，不做凑数的人情。这不是 RAG 独有的取舍：上下文是稀缺资源，往里放的每一块都要值回它的 token。

## 可溯源，以及开卷救不了的事

开卷考试最大的红利是可溯源：答案能带上「【来源：《回款管理办法》§3.2】」这样的标注，用户可点开原文核对，这在制度问答、客服与合规场景里是闭卷模型给不了的东西。但开卷救不了检索落空：如果 query 与库内内容在语义上不沾边，检索环节取不回有用资料，模型仍可能借着零星弱相关碎片硬答一段，幻觉并未根除。防线只有一道：把「资料不足就明说找不到」写进 system prompt，并把「未找到」视为合格回答而不是失败。本课是模块 R 的总览，后续两课将深入：R02 讲语义空间与嵌入选型，R03 掰开切块与检索策略。
